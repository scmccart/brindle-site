# CLAUDE.md

The website for Brindle, a GPU-accelerated terminal emulator for Linux and Windows (https://github.com/scmccart/brindle). This repo holds only the site: Astro 7, React islands, Tailwind 4 and shadcn/ui (`components.json`: radix base, Nova preset, lucide icons). It is published to GitHub Pages.

## Commands

```sh
npm ci
npm run dev        # local preview
npm run build      # static output in dist/
npm run typecheck
npm run lint
```

## Rules

- **Static output only.** GitHub Pages serves files: no SSR, no API routes, no server actions, no `output: "server"`, no adapter. Interactive parts are React islands (`client:*`).
- **Base path.** Until there is a custom domain the site is served under `/brindle-site/`, so internal links and assets go through `import.meta.env.BASE_URL`, never a bare `/`.
- **Colours come from Brindle.** `src/styles/brindle-tokens.css` is generated by `brindle --export-ui-tokens` and attached to every Brindle release as `brindle-ui-tokens.css`. Never edit it by hand and never hard-code a colour: use the shadcn tokens (`bg-background`, `text-primary`, …) and the `--terminal-*` variables for terminal mock-ups. Each built-in theme is a `[data-theme="NAME"]` rule; `brindle-light` is `:root` and `brindle-dark` is `.dark`.
- **shadcn components** are added with `npx shadcn@latest add <name>` (or the shadcn MCP server), not written from memory. Don't edit `src/components/ui/*` beyond what shadcn generates; wrap them instead.
- Facts that change with releases (version, download links, install commands, feature list) live in one data file, refreshed from the latest Brindle release, not scattered through pages.
- Check pages visually (desktop and mobile widths, light and dark) before calling a change done.

## Commits

Conventional Commits (`type(scope): subject`, lowercase subject, header ≤ 100 characters), as in the Brindle repo.
